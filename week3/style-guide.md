# Style Guide for the GitHub Repository Task

## Scope

Apply these six rules to an English guide for a first-time GitHub user in a desktop browser. The rules follow slide 18 of the Chapter 3 writing-style lesson. Examples below show actual changes from [before.md](before.md) to [after.md](after.md). This is a project style guide, not a claim of compliance with a formal standard.

## R1 State the starting point

State the account, platform, access, and task scope before the procedure.

- **Before:** The excerpt begins with “Open GitHub” and places signing in inside step 1.
- **After:** “Sign in to GitHub.com in a desktop browser with the English interface. Use your personal account and have a repository name ready.”
- **Why:** Readers can prepare before starting the procedure.

## R2 Begin steps with a verb

Start each numbered instruction with a direct action verb. Use the current interface label for the control being operated.

- **Before:** “Check the box labeled ‘Add a README file.’”
- **After:** “Set **Add README** to **On** to initialize the repository with a README file.”
- **Why:** The instruction states the action and setting directly. The control label is updated against GitHub Docs.

## R3 Keep key terms consistent

Use “repository” for the container, “README file” for the document, and `README.md` for its filename. Avoid vague substitutes when naming an object matters.

- **Before:** “This file provides basic information about your project and serves as a starting point for future documentation.”
- **After:** “Set **Add README** to **On** to initialize the repository with a README file.”
- **Why:** Naming the README file explicitly keeps the action tied to the correct object.

## R4 Put conditions first

Place a condition before the action it controls.

- **Before:** “You may also add a short description to explain its purpose.”
- **After:** “If you want to explain the repository's purpose, enter a short description.”
- **Why:** Readers know whether an optional action applies before performing it.

## R5 Use numbered steps

Present actions in sequence. Give separate numbers to actions at distinct interface stages when this makes the procedure easier to follow.

- **Before:** “Click the ‘+’ icon in the upper-right corner and select ‘New repository’ from the dropdown menu.”
- **After:** “1. Open the **+** menu in the upper-right corner.” followed by “2. Select **New repository**.”
- **Why:** Each interface action has a clear position in the sequence.

## R6 Name the result check

Describe observable evidence of success, with specific items for the reader to inspect.

- **Before:** “The repository is successfully created if its homepage displays the repository name, a ‘Private’ label, and a README.md file with its content.”
- **After:** A checklist names the owner and repository name, the **Private** label, and `README.md` with its displayed content.
- **Why:** Separate checks make success easier to verify and include ownership.
